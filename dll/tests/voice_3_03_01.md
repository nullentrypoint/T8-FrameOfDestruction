# Voice address validation: Tekken 8 3.03.01

The voice addresses are loaded from the same runtime configuration as frame data:
`<DLL directory>/T8FrameOfDestruction/config/memory_address.ini`.
Sections `VoiceIdentity`, `VoiceSteam`, `VoicePeerTrace` and `VoiceProfileTrace`
contain the RVAs. Every field is a single nonzero hexadecimal 32-bit RVA; only
`steamclient_method_rva` is relative to `steamclient64.dll` rather than the game.
All voice sections must be deployed together. Missing or malformed fields disable
the voice memory layout and report the offending key; there are no compiled
address fallbacks. Loading occurs at diagnostic/voice worker startup, so restart
the mod after editing the INI.

Future address-only changes need just an INI update. Instruction signatures,
interface names and data-structure validation remain in C++; changes to those
still require a code update. Profile tracing validates the RIP-relative target
against `dialog_rva` instead of embedding the relocation displacement in a
signature. Peer return sites are derived from configured call sites plus the
validated instruction lengths.

patterns also matched; the latter references the `steamid` string.

The production `PlayerIdentityReader`, invoked through its external read
callback against the live process, returned `Ok` with one local record (role 1).
All four strings passed its existing length, capacity, content, terminator and
repeat-read checks. Platform fields matched. No captured IDs are included here.

## Exit crash regression

Four 2026-11-12 exit crashes had `IsRequestingExit=true` and the same call chain:
`SteamDiagnostics::Run -> SteamChannelProbe::Impl::RefreshPeer ->
SteamPeerProfile::Refresh -> SteamAPI_ISteamFriends_RequestUserInformation ->
steamclient64`, ending in an access violation at address `0x18`. Symbols were
resolved from the installed ASI's adjacent matching PDB. The diagnostic log had
already recorded the identity container becoming unavailable before the crash.

Binding now installs a guard on the same SDK's exported `SteamAPI_Shutdown`
before acquiring interfaces. That guard signals and joins the voice worker,
including SDK-dependent connection cleanup, before forwarding shutdown. Normal
explicit unload removes the guard after stopping the worker. If SDK shutdown
has begun, F11 does not unload the detour while it can still be on the game's
stack. Process-termination `DllMain` also skips GPU/hook cleanup under the loader
lock; explicit unload still uses its cleanup worker.

The headless smoke test now exercises the real shutdown detour with a worker:
the original shutdown must observe worker exit and closed handles/log, repeated
shutdown forwards without using closed resources, and explicit stop removes the
guard before a subsequent shutdown. These tests and the Release/x64 build pass.
The rebuilt ASI and matching PDB were deployed with backups; the user confirmed
that normal game exit no longer crashes. Expected log order is `stopping worker before
SteamAPI_Shutdown`, worker cleanup, then `passive Steam diagnostics stopped`.
